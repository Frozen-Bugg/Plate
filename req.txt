OVERLOAD — EVERYTHING NEEDED TO RUN AND DEVELOP THIS PROJECT
============================================================

Dart/Flutter has no requirements.txt: the app's packages live in app/pubspec.yaml
and are installed with `flutter pub get`. This file covers the toolchain around
them — what to install on a new machine, in order.

Fast path on macOS:  bash scripts/setup.sh   (installs what it can, checks the rest)
Fast path on Windows: see section 9 (Android + web only; scripts/setup.sh is macOS-only)
Verify at any point: cd app && flutter doctor && flutter analyze && flutter test

Versions below are what this project was built and verified with (2026-09-12).
Newer usually works; older Flutter will not (the code uses Dart 3.11 features).

2. ANDROID (to build and run on Android)
------------------------------------------------------------

Android Studio (easiest way to get the SDK)   brew install --cask android-studio
Then in Android Studio > SDK Manager install:

  Android SDK Platform            36        (compileSdk/targetSdk = 36)
  Android SDK Build-Tools         36.0.0
  Android SDK Command-line Tools  latest    <- flutter doctor fails without this
  Android SDK Platform-Tools                (adb)
  Android Emulator
  NDK                             28.2.13676358   (Flutter's default for 3.41.9)
  minSdk is 24, so any emulator image API 24+ works. This project used:
    system image  android-36 / google_apis_playstore / arm64-v8a

Environment (add to ~/.zshrc):
  export ANDROID_HOME="$HOME/Library/Android/sdk"
  export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH"

Accept licences:     flutter doctor --android-licenses
Create an emulator:  flutter emulators --create --name pixel
Launch it:           flutter emulators --launch pixel

Gradle 8.14 and AGP 8.11.1 / Kotlin 2.2.20 are downloaded automatically by the
Gradle wrapper on the first build. Nothing to install by hand.

4. ACCOUNTS AND SERVICES
------------------------------------------------------------

Supabase (free)      https://supabase.com — Postgres, auth, storage.
  Needed values:     Project URL, publishable key (Project Settings > API)
  Apply the schema:  npx supabase login
                     npx supabase link --project-ref YOUR-REF
                     npx supabase db push
                     (or paste supabase/migrations/*.sql into the SQL editor)

PowerSync (free)     https://powersync.com — offline-first sync.
  Needed value:      instance URL
  Setup:             create the powersync_role in Postgres, connect the instance,
                     set client auth to Supabase Auth, paste
                     powersync/sync-streams.yaml into Sync Streams. See README.

Anthropic API        https://console.anthropic.com — only from Phase 4 (the AI
                     coach service). Not needed to run the app today.

Optional:
  Google Cloud OAuth clients (iOS + Web)  for Google sign-in
  Apple Developer account                 for Sign in with Apple

5. PROJECT SETUP (after the toolchain is in place)
------------------------------------------------------------

git clone <your repo>  &&  cd Gym

cp app/config/dev.example.json app/config/dev.json
  Fill in SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY, and POWERSYNC_URL if you have
  one. This file is gitignored and never committed — copy it across yourself or
  re-read the values from the dashboards. Without POWERSYNC_URL the app runs
  local-only; without the two Supabase values it shows a setup screen.

cd app
flutter pub get                  # installs every package from pubspec.yaml
dart run build_runner build      # generates Drift code (lib/core/db/app_database.g.dart)
flutter analyze && flutter test  # should be clean, 9 tests passing
flutter run --dart-define-from-file=config/dev.json

8. KNOWN GOTCHAS ON A NEW MACHINE
------------------------------------------------------------

TLS interception (Zscaler, corporate proxies, some antivirus)
  Symptom: Gradle can't download from services.gradle.org, and the app fails
  sign-in with "CERTIFICATE_VERIFY_FAILED: unable to get local issuer
  certificate". Cause: curl and browsers trust the proxy's CA from the system
  keychain, but Dart and Java ship their own trust stores and reject it.
  Fixes: develop off that network, or add the proxy's root CA to Dart's
  SecurityContext in debug builds and to Java's cacerts.

Gradle wrapper uses the -bin distribution (app/android/gradle/wrapper/
gradle-wrapper.properties). Keep it that way: -all is a 224 MB download with no
benefit here.

flutter doctor complaining about cmdline-tools is not cosmetic — Android builds
fail without it and without accepted licences.

`dart run build_runner build` must be re-run after changing Drift tables in
app/lib/core/db/tables.dart, or the app won't compile.


------------------------------------------------------------
9. WINDOWS SETUP (Android + web only — no iOS without macOS)
------------------------------------------------------------

Verified end to end on Windows 11 (26200) on 2026-09-12: analyzer clean,
9/9 tests passing, Flutter 3.41.9 / Dart 3.11.5.

Run these in PowerShell. Everything installs per-user; no admin needed except
where winget elevates on its own.

9.1 Toolchain via winget
  winget install --id Git.Git --exact
  winget install --id OpenJS.NodeJS.LTS --exact
  winget install --id Microsoft.OpenJDK.17 --exact
  winget install --id Google.AndroidStudio --exact

  Microsoft's OpenJDK 17 is used instead of the Mac's temurin@17 — same LTS,
  no click-through licence, and winget has it. It lands in
  C:\Program Files\Microsoft\jdk-17.<x>-hotspot.

9.2 Flutter SDK (no winget package — official zip)
  Invoke-WebRequest -Uri https://storage.googleapis.com/flutter_infra_release/releases/stable/windows/flutter_windows_3.41.9-stable.zip -OutFile C:\src\flutter.zip
  Expand-Archive C:\src\flutter.zip -DestinationPath C:\src

  Install to C:\src\flutter, NOT Program Files: the path must have no spaces
  and stay short, because Gradle and Flutter build paths hit the Windows
  260-character limit in deep package directories.
  Expand-Archive takes ~10 min on this 1.8 GB archive (~18k files). Windows'
  bundled tar is much faster: tar -xf C:\src\flutter.zip -C C:\src

9.3 Android SDK — headless, no Android Studio wizard
  IMPORTANT: pin cmdline-tools 19.0. Do NOT take "latest".
  cmdline-tools 22.0+ replaces the classic sdkmanager with a new `android` CLI
  that crashed here (exit 9 / 0xC0000409) on every command that hits the
  network, after only partly installing. Version 19.0 still ships the classic
  sdkmanager and works:

  curl -L https://dl.google.com/android/repository/commandlinetools-win-13114758_latest.zip -o clt.zip
  tar -xf clt.zip
  # move the extracted cmdline-tools folder to:
  #   %LOCALAPPDATA%\Android\Sdk\cmdline-tools\latest

  Then, with JAVA_HOME and ANDROID_HOME set (see 9.4):
  sdkmanager --licenses            # answer y to each
  sdkmanager "platforms;android-36" "build-tools;36.0.0" "platform-tools" "emulator"
  sdkmanager "ndk;28.2.13676358"
  sdkmanager "system-images;android-36;google_apis_playstore;x86_64"

  Note the system image is x86_64, not the Mac's arm64-v8a.
  sdkmanager 19.0 prints "only understands SDK XML versions up to 3 but ...
  version 4 was encountered" — harmless version skew, installs fine.

9.4 Environment (User scope, persists across reboots)
  [Environment]::SetEnvironmentVariable('JAVA_HOME','C:\Program Files\Microsoft\jdk-17.0.20.101-hotspot','User')
  [Environment]::SetEnvironmentVariable('ANDROID_HOME',"$env:LOCALAPPDATA\Android\Sdk",'User')
  Add to the User Path:
    C:\src\flutter\bin
    %LOCALAPPDATA%\Android\Sdk\platform-tools
    %LOCALAPPDATA%\Android\Sdk\emulator
    %LOCALAPPDATA%\Android\Sdk\cmdline-tools\latest\bin
    %JAVA_HOME%\bin
  Open a new terminal afterwards — existing ones keep the old environment.

  flutter config --android-sdk "$env:LOCALAPPDATA\Android\Sdk"

9.5 Expected flutter doctor result
  Android toolchain, Chrome, Windows Version and Network resources all pass.
  "[X] Visual Studio not installed" is EXPECTED and safe to ignore — that is
  only for Windows desktop builds, which this project does not target.

9.6 Differences from the macOS instructions
  - scripts/setup.sh is bash and macOS-only. Run it under Git Bash if at all;
    it calls brew, which does not exist here. The steps above replace it.
  - No iOS, no Xcode, no CocoaPods. Section 3 does not apply.
  - Section 5 says `cd Gym`; the repo directory is whatever you cloned into
    (here: C:\Project\Plate).
  - Use `copy` or the editor rather than `cp` for app\config\dev.json unless
    you are in Git Bash.
